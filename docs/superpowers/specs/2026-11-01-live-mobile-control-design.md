# Live mobile control, without new authentication

The user requests mobile device/channel/meter/control views, automatic browser updates, bounded controls and coordinated concurrent editing. The user explicitly defers all new access-protection work. Keep existing same-origin mutation checks and firmware/admission/uncertain-outcome safeguards. Scope remains the local network. Java21 server remains headless and usable without a UI. Existing UI and API are extended rather than replaced; all product text and maintained docs are English. No audio writes to physical hardware.

## Approach

Use Server-Sent Events (SSE) for cached server-to-browser state/meters; parameter commands remain HTTP. This fits one-way telemetry and preserves existing request keys and typed outcomes. Polling remains a compatibility fallback when the new endpoint is unavailable; ordinary connected sessions should use one EventSource rather than repeated meter/state HTTP polling. Browser-independent optimistic concurrency belongs in the Java runtime, not solely in browser preflight. Authentication, users/roles and Internet deployment are deferred.

## Shared API/runtime contract (backend worker owns API/runtime + parameter HTTP)

Add public ControlStateDto(String dspId,String instanceId,long revision,boolean connected,List<ChannelDto> channels,CapabilitiesDto capabilities,SettingsCacheDto settingsCache). Defensive immutable list. instanceId is a random UUID for each concrete runtime lifetime, revision is monotonic within that lifetime; cached controls/capabilities/connection/settings-cache changes advance it, meter samples do not. etag() returns a quoted strong tag "instanceId.revision". GET/read paths must remain RAM-only and responsive while I/O is in progress. No root physical target in managed mode.

Add compatible default methods on an API extension inherited by DspService: getControlState() and writeParameterConditional(ParameterWriteRequestDto request,String expectedEtag,boolean interactive), default unsupported for older providers. New DspControlConflictException extends IllegalStateException and carries currentState(). Runtime performs comparison inside existing bounded parameter transaction admission immediately before transmission, so competing participating writes cannot both use a stale revision. Retain65-operation admission, fast try-lock behavior, session identity/firmware gating and typed ACK/VERIFIED/REJECTED/UNCERTAIN semantics. A false condition emits no audio command. Current state projection must also detect legacy cached control updates; direct external device edits are observable only when actually received by the server.

HTTP GET /api/v1/dsps/{id}/control-state returns ControlStateDto and ETag. POST existing /parameters/write optionally accepts If-Match with one exact quoted tag. Missing header keeps current legacy behavior. With a header use writeParameterConditional; interactive flag follows Prefer:wait=0. Mismatch returns412 with {error:"conflict",errorCode:"revision_conflict",message:...,transmitted:false,current:ControlStateDto}. Existing typed response shapes remain unchanged otherwise. Idempotency cache fingerprints also include the exact If-Match condition; duplicate same-key retries replay before reevaluating the condition, and changed condition/body/target conflicts. Retain resolved service identity binding.

## SSE contract (parent owns new HTTP classes/features)

GET /api/v1/events?dspId=ID (optional query, absent = devices-only). Standard Servlet whiteboard registration, asyncSupported=true, exact endpoint; add Karaf http-whiteboard feature without changing existing API/app aliases. New connections and reconnections always receive fresh cached state, never replay commands or initiate reads/connect/refresh. No durable event history is claimed.

Named events: devices -> existing /dsps envelope {defaultDsp,dsps}; state -> ControlStateDto for selected target; meters -> existing envelope {dspId,connected,meters:MeterStateDto}; heartbeat -> {serverTimeEpochMs}; removed -> {dspId,instanceId,message}. Terminal removal/replacement sends removed and closes, so the client reloads selection. Check concrete service identity to prevent same-ID retargeting. Initial unknown selected ID returns404 before streaming. Missing/invalid DSP ID validation is explicit. Stream errors close the stream; do not silently invent empty state.

Shared sampler per active target, about200ms for cached meters/state, plus devices about1000ms and heartbeat10s. Never create physical meter pollers per subscriber. Bound subscribers (128 default), coalesce each subscriber's latest pending state/meters/devices; retain at most one in-flight frame and bounded pending slots. Use Servlet nonblocking output (WriteListener/AsyncContext); a slow/disconnected browser must not block sampler or other clients. Disconnect, async error/timeout, unbind/deactivation and last subscriber removal release resources. Default idle async timeout can be disabled while heartbeats and bounded resources govern lifetime. Event IDs are delivery cursors only; state instanceId/revision govern freshness.

## Mobile contract (frontend worker owns web assets and JS/browser tests)

Extend existing mobile channel cards and device selection. Automatic updates populate controls and level displays with no DSP readback. One EventSource per visible page, close on selection/hidden/unload, reopen with fresh cached state on return. Device-list updates handle additions/removals. Ignore late events, old instance events and decreasing revisions. Same-ID replacement clears drafts/old state and requires new target binding. SSE lost/reconnecting/stale states are visible and disable unsafe edits until current data is available. Existing polling fallback is only for unsupported SSE, not a second permanent update path.

Use control-state as snapshot authority where available. Before a write, fresh RAM snapshot may recheck the field's draft baseline, then send its ETag as If-Match (and existing random Idempotency-Key, Prefer wait=0). Backend412 is a definite unsent conflict; show refreshed current state, preserve useful draft feedback, never automatically overwrite/retry. ACK does not certify physical readback or a full settings snapshot. After ACK, a cheap control-state cache refresh or SSE updates display; compare instance/revision so a late ACK/GET cannot overwrite newer pushed state. Preserve uncertain-device recovery rules.

Gain previews locally, sends final value on release/keyboard edit, obeys capability quantization/ranges, allows only one pending command and imposes a short bounded interaction rate without building a command queue. Existing mute/phase/delay semantics stay. Pending, busy, ACK, conflict and uncertainty must be distinguishable. Do not add names/accounts when authentication is deferred. Existing English UI styling can be refined for phone layout but no new branding framework or Node runtime dependency.

## Packaging and deployment

Parent adds optional webEnabled boolean to persistent server settings, default false when absent (backward compatible). Launcher writes web PID enabled accordingly. Default package remains API-only; local user-owned instance will opt into webEnabled=true after testing. SSE is an API capability independent of UI. Keep registry bytes and LAN port8182, never contact the physical DSP automatically. Produce/push reviewed source, clean package and CI; install as a new immutable release, preserve previous release for rollback, use existing persistent dsp408-server.service. Do not change lingering/auth settings.

## Acceptance/review focus

Backend RED/GREEN: unchanged/meter-only snapshots stable revision, actual cached mutation advances, stale conditional write no transmission, two clients same tag cannot overwrite, busy/uncertain compatibility, delete/re-add identity, same-key condition fingerprint. SSE tests: bounded slow consumer, shared sampling, initial snapshot/reconnect, device removal, nonblocking output and cleanup. Actual packaged JVM: SSE frames arrive promptly, two subscribers add no physical reads, one stale writer412, no accidental duplicate wire write on retry. Browser tests: phone/desktop, pushed meters/state, two browsers, stale/pending HTTP ordering, lost/reconnected stream, rate limiting, hidden pages, uncertain recovery. Default offline package and web-enabled package both pass; whole workspace and CI stay green. One independent whole-change review and meaningful regression fixes. No physical audio writes.
